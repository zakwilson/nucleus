## defmacro

- `(defmacro name (params...) body...)` defines a compile-time macro. The body runs in the JIT and receives unevaluated `Node*` arguments; the returned `Node*` is re-emitted at the call site.
- Macro JIT function signature: `ptr @__macro_<sanitized_name>(ptr %__args.arg)` where `%__args.arg` is a `Node*[]` pointer.
- Macro names are sanitized before use as IR identifiers: hyphens, `!`, `?`, etc. are replaced with `_`. This is required because LLVM IR identifiers can only contain `[A-Za-z0-9_.]`.
- `(gensym)` inside a macro body returns a fresh `__gs_N` symbol `Node*` for manual hygiene. `nucleus_gensym` is defined as a `defn` in `nucleusc.nuc` and exported from the self-hosted binary via `-rdynamic`.
- `(funcall-ptr-1 fn arg)` calls a `ptr` function pointer with one `ptr` argument, returning `ptr`. Used by the self-hosted compiler's `emit-macro-expand` to call macro JIT functions.
- `:rest` variadic parameters: `(defmacro name (a b :rest rest) ...)` — `:rest` must be second-to-last in the param list. The last param receives a cons list of remaining args. `MacroDef.variadic` flags variadic macros; `emit-macro-expand` builds the rest list in reverse order with `make-cell`.
- The `->` threading macro uses `_` as a positional placeholder inside forms. `_` is only special within `->` — it's an ordinary symbol elsewhere. If no `_` appears in a form, thread-first (insert after head). Implementation rebuilds the form using quasiquote reverse-and-rebuild (not `make-cell`) so it works at JIT time.
- Macros that reference `*Node`, `NODE-CELL`, `NODE-SYM` etc. (like `->` and `dotimes`) need the `Node` type in scope, which the prelude provides via `(import node)`. A macro body may also **call ordinary program `defn`s** (e.g. `node-at`, `intern-symbol`): the macro/CT JIT module re-`declare`s each one, and **which definition that `declare` binds to is decided by provenance, not by the linker — see the next bullet**. This is automatic — `emit-defn` records every main-module defn's signature (`g-program-defns`/`ProgDefn`) and `emit-call-with-args` emits the declare into the JIT module on first reference (`macro-jit-ensure-decl`) — as does `emit-symbol-ref-bound`'s function-materialization branch, since a body may NAME a defn (a function pointer) as well as call it (Stage 20 L5). Only main-module defns are re-declared; externs/`(include …)` declarations are already in `g-decl-bufp` (copied into the JIT module), and a defn *defined inside* a CT block is skipped (it already lives in that module). Note: `abi-print-param` writes to `g-out` (the def stream), so the declare's param types are formatted straight into `g-decl-out` instead.
- **Provenance decides what a name in a macro body means, not the linker (Stage 20 L4, design/stage20-macros/macro-call-linking.md §3.1).** A callee resolves to the **compiler's** copy when both conditions hold: its defining file is under the library root this invocation resolved `lib/prelude.nuc` through (`g-ct-lib-root`, `path-under-ct-lib-root`), **and** the running binary exports the symbol (`host-exports?`). That pair is the compile-time runtime — `alloc-node`, `make-cell`, `intern-symbol`, `node-at` — and it stays on the host so one arena, one intern table and one `Node` layout serve the whole compilation (§3.2). Everything else resolves to the **program's** definition, copied span-for-span out of `g-def-buf` into a *compile-time mirror* module that `ct-mirror-flush` adds to the main JITDylib immediately before the macro's `LLVMOrcLLJITLookup`. So a macro body may call its own helpers, share them with another macro, and recurse through one; a `lib/` module the compiler does not link is the program's too; and a program name that collides with one of the 1,658 ordinary-Nucleus-looking names on the `-rdynamic` roster now runs the PROGRAM's — `--warn-ct-shadow` (on by default) says so once. What is still unsupported: a callee defined **below** the macro has no `ProgDefn` when the body is compiled, so it gets no declare — **L5 makes that a located error** (`macro 'probe' calls 'helper', which is defined later in this unit`, with a note; a `compile-time` block gets the same message naming the block), as it does for the two refusals `ct-mirror-flush` records silently. The check is deliberately **four** conditions, not the one "no `ProgDefn`" suggests: a local or function-pointer value is not a global, an extern / C-header import / intrinsic is already in `g-decl-stream`, and a `defn` a CT block defines itself is `define`d in that very module and would otherwise be diagnosed wrongly (`g-ct-module-defns`). A **generic** callee takes the same message, correctly — its stamp drains at the end of the unit — and stays unsupported. The roster also remains an unversioned API, so nothing in `lib/` may reach into it (`macroexpand-form`, `desugar-form`, `find-macro`). **A program GLOBAL is part of the closure too (Stage 20 L6)**: the mirror copies its `@g = …` span — backing `@g.data` included — rewriting a `defvar-`'s `internal` to `weak_odr` so a second flush can bind the first's copy, and a host-exported `lib/` global (`g-arena`) stays a `declare` so §3.2's one arena survives. There is no single emitter chokepoint for a global reference the way `macro-jit-ensure-decl` is for a call — a read, a `set!`, an `&g` and a member GEP each spell `@g` by their own route — so the module's own finished IR text is scanned instead (`ct-scan-body-globals`). If the global's initializer is still queued, the mirror emits its own `@__ct_init_N` from the jobs of the globals IT defines and calls it before the lookup; `g-init-drained` is **never** advanced, so the program's `@__nucleus_init` still carries every one of them. A flush can NEST (that initializer is emitted with `emit-node`, which expands macros), so the per-flush vectors are saved and restored, not merely reset. The REPL reaches the same end by its own route (it JIT-compiles every top-level form) and the mirror is gated off there. **Cross-compilation refuses the mirror (Stage 20 L8, §5.9)**: the spans are `g-def-buf` text, ABI-lowered for `--target=`, and the mirror is a host-triple module — so when a flush is required and `g-target-triple` differs from `((as ref:Target g-host-target) 'triple)` the compiler refuses with both triples named. The comparison is on the two **triples**, not on `g-target` vs `g-host-target`: `target-init` builds a second `Target` for any `--target=`, the host's own triple included, so the object test would refuse an identical ABI. Only a *flush* is refused, so a body that names nothing but the compile-time runtime cross-compiles untouched — which is every macro `make avr-test` and the RISC-V targets reach, and is also why "this unit needs no mirror" is now an **observable** property: a cross-target compile that succeeds flushed nothing (`src/nucleusc.nuc` cross-emits clean for `riscv64` and both Windows triples). `--warn-ct-shadow` covers a shadowed **global** as well as a call (`warn-ct-shadow-global`), on the same measurement that lets it default on: zero fires over a 478-file sweep of `examples/`, `lib/`, `tests/` and `src/`.
- **A macro ARGUMENT may be computed, by marking it `~` (Stage 20 C1/C2, design/stage20-macros/computed-macro-arguments.md).** `~e` in macro-argument position — and nowhere else; every other position keeps `unquote outside quasiquote` — compiles `e` as an anonymous zero-parameter macro body (`ct-eval-node`, a synthetic `MacroDef` with `pcount` 0 handed to `compile-macro-body` with the new `is-arg` flag), flushes its roots, looks up `@__ct_eval_N` and substitutes the `(raw Node)` it returns. Everything in bullet 11 is inherited rather than rebuilt, because this *is* that path: the mirror, the closure walk, `--warn-ct-shadow`, L5's forward-reference refusal, L6's nested flush and L8's cross-target refusal all fire, with the subject switched from the macro to the argument (`g-ct-body-arg` → `ct-body-who`), since the fault is in the CALLER's text. The substitution is at the top of `expand-macro-call`, before the arity checks, so "expects N args, got M" counts what the macro receives; `ct-subst-args` rebuilds the call only when a `~` is present, so every other program reaches the body on the reader's own node and the bootstrap is byte-identical. **The type check is new and belongs to this path only**: `ct-eval-require-node` rejects a body value that is not a Node pointer, which is the hole `~` inside a quasiquote still has (`~5` → `integer constant must have integer type`, quasiquote-levels.md §10.3 — pre-existing and still open). **C3 adds `~@e`**, the splice: the same evaluation, but the list the body returns is substituted as *N* arguments rather than one node, which is what serves the `:rest` family (`macfoldr`, `macfoldl`, `+`, `case` and any user `:rest` macro, none of them changed). Only the caller differs — `ct-subst-args` normalizes each argument to the list of elements it contributes, so an empty result contributes zero arguments and the arity check still counts what the macro receives. The value's *shape* is checked separately from C1's type check and after it (`ct-eval-require-list`), because a list is a property of the value and only knowable after the JIT call; the whole list is walked, so a dotted tail is refused rather than dropped. The REPL needs no gate (probed: `~e` works at the prompt, `ct-mirror-flush`'s `g-interactive` early return is enough because the REPL JIT-compiles every top-level form anyway); the one REPL limitation is pre-existing and unrelated — a prompt-typed `defn` whose body builds nodes fails `use of undefined value '@alloc-node'`, so the producer has to be a quasiquote or come from an import.
- Note: gensym'd symbols cannot be used as typed `let` binding names with the `~sym:type` quasiquote syntax — the reader parses `sym:type` as a single token. Nor with `~sym:(Type)`: since Stage 21 PK-2 the colon-paren fuse fires on a reader-macro operand, so that reads as `(unquote (sym (Type)))` — a call evaluated at expansion time, not a binding. Workaround: the list form `(~sym Type)`, gensym-free macros where possible, or `~sym` only in value position.
- Macro output is desugared before compilation: any colon-typed symbols in binding positions (defn name, let bindings, params, etc.) are split into canonical list form `(name type)`. Typed symbols in value/expression positions are NOT desugared — they stay as symbols and are handled by `split-typed` in the compiler.
- The C `Node` struct uses separate fields (not a union) to match the LLVM/Nucleus `{ i32, i32, i64, ptr, ptr, ptr }` 40-byte layout. This is required for JIT-created nodes to be readable by the C bootstrap.
- **A macro body cannot call `die-at`/`report-at`; it rejects its call site with `(macro-error node "literal")` (Stage 20 M3).** The diagnostics live in `src/diagnostics.nuc`, imported only by the compiler's own source, so a `(defmacro m (x) (die-at (x line) "...") x)` fails with `unknown: die-at` (Stage 15 W4d). `macro-error` is the special form for the job — a located error at `node`'s line, message a string literal, aborting the expansion (`docs/macros.md`). **What a body still cannot survive is a null dereference**: `(x 'car)` on a null `(raw Node)` runs inside the compiler process and kills it with SIGSEGV before any `macro-error` fires — `expand-macro-call` (`src/nucleusc.nuc`) calls the JIT'd body with no fault boundary. So a shape check is a short-circuit guard chain in a load-bearing order, `context/conventions.md` §"Member access on a null node in a macro body kills the COMPILER"; `macmap` has one, and `doseq`/`doseq-iter`/`dotimes` do not yet (Stage 21 overview, rough edges).

## compile-time JIT

- The `(compile-time body…)` form links the system LLVM (19+) via the LLVM ORC LLJIT C API.
- A single LLJIT instance is shared across all `compile-time` blocks in one compilation run (lazy init on first use).
- Each `compile-time` block generates a uniquely-named entry function `@__compile_time_main_N` to avoid symbol collisions.
- CT printf output goes to stderr (via a `dup`/`dup2` redirect) so it doesn't corrupt the IR emitted to stdout.
- An `llvm-dev` package (version 19+) must be installed for the LLVM C API headers; `llvm-config` provides the right `--cflags`/`--ldflags`/`--libs`.
