Nucleus is a replacement for C using Lisp style syntax and macros with LLVM as its target. It is a low level systems programming language meant to manipulate memory directly, and when required, unsafely.

## Goals

### True drop-in substitute for C

- Zero mandatory runtime overhead relative to C
- C interop - include C libraries and call C functions with no overhead
- Use C structs and arrays natively

### Lisp syntax

- The language is written as a direct representation of linked lists of symbols, numbers, and strings
- Reader macros add syntactic sugar for things like dereferencing pointers
- User-defined reader macros will be possible
- A vector type like Clojure could be useful, or at least improve readability
- Member access for arrays and structs by calling them like functions - maybe provide a way to overload this

### Full language at compile time

- Macros run at compile time have full access to the Nucleus language, as in most Lisps
- Language features and libraries required for macro expansion may not be necessary at runtime
- Something like Common Lisp's eval-when or a compile-time-only include form is probably required for some advanced macros

### Optional compiler at runtime

- It must be possible to compile and load code at runtime
- Because it adds overhead, the compiler is available as a library
- This allows eval, a REPL, and the ability to interrogate compile-time metadata during development
- For development, a REPL harness can load code files so the developer can use the REPL without the code including it

### Macros are the killer feature

- Macros allow significant abstraction at compile time without requiring runtime overhead
- Reader macros allow sugar for common syntactic patterns

## Design principles

- Small core - it's better to have few builtins and more libraries
- Few special forms - it's especially better to have few builtins with special behavior
- Many macros - where ergonomics or expressiveness require special behavior, macros are the preferred implementation
- Macros vs functions - In Lisp, it is conventional to prefer functions over macros wherever possible. In Nucleus, runtime overhead is is equally important.
- LLVM native - Nucleus targets LLVM and relies on its infrastructure to simplify implementation when possible.
- C-compatible - Nucleus is a drop-in replacement for C with a superset of C's functionality. It must be able to use any C library's functions and data structures, but not its macros. Likewise, any functions and data structures from a Nucleus library must be consumable from C.

- [deferred/compiler-api-surface.md](deferred/compiler-api-surface.md) — **deferred, no plan, raised 2026-09-15**: turning `-rdynamic`'s accidental 2,285-symbol export surface (1,658 of them ordinary Nucleus identifiers) into an intentional one. The standing rule — nothing in `lib/` may name any of them — forbids tooling and accidental capture in the same breath: `macroexpand-form`/`desugar-form`/`find-macro` are cited as what must not be touched and are exactly what an expander, formatter or linter needs, while `node-at` in `lib/error.nuc` is legitimate only because the compiler links `lib/node.nuc` and nothing distinguishes the two. Three facts frame it — **nothing enforces the rule** (no audit unit, no compiler check); Stage 20 L4's `from-lib ∧ host-exports?` gave it teeth it lacked when written, so a `lib/` file spelling one of the 1,658 now resolves to the *compiler's* definition and cannot shadow it; and `host-exports?` (`src/nucleusc.nuc:1444`) asks the **running binary**, so narrowing exports narrows provenance for free — the visibility change and the semantic change are one change. The tractable cut is `lib/` (export wholesale) against `src/` (hide but for a named list), which is the boundary provenance already computes via `path-under-ct-lib-root`; the floor is whatever a REPL session resolves from the process, which is the first thing to measure. Five options: **A** enforce the existing rule with an audit unit (small, worth landing regardless), **B** curated export list replacing blanket `-rdynamic`, **C** name the API behind Stage 12 N4's `set-ir-prefix` (B decides what is reachable, C how it is spelled), **D** tier it stable/opt-in on the `unsafe/` convention, **E** generate a CT `.nuch` and check it like the 87 existing headers. **D is the policy question and has to be answered first** — what gets promised is not the implementation's to decide, and the promise, not the code, is the expensive part. B carries a boot convergence (linkage is in the committed IR) and needs a per-object-format story, since the compiler cross-emits to two Windows triples

- [stage17-native-strings/borrow-conventions.md](stage17-native-strings/borrow-conventions.md) — Stage 17's one **open language decision**, raised by A2/A3 and wanted before B1: by-value producers (`strview-from-cstr`, `strview-sub-bytes`, `strview-trim*`, `split-iter-next`) meet by-reference consumers (every `ByteStr`/`Str` method, `strview-byte-len`, `strview-eq`), so `(addr-of …)` appears at every site. Establishes that this is **structural, not a style lapse**, and that both uniform conventions are unreachable: the producer side must be by value (the alternatives are the `malloc` gap #7 deleted and the `alloca` dance gap #8 deleted) and the consumer side must be by reference (`ByteStr`/`Str` bind `Self` to both `StrView` *and* `String`, and `String` has `Drop`, so a by-value receiver is a move on every read-only query). The real question is who bridges the seam — the call site or the compiler. Surveys the precedent (Rust/Go auto-ref the *receiver* only, which is where Nucleus already is; C++ `&`, C# `in`, Pascal `var`, Ada modes, D `ref` do it at every parameter; Zig keeps it out of signatures entirely) and the line all of them draw: **no language lets a mutating reference silently bind a temporary.** Since Nucleus's `(ref T)` conflates read and write, unrestricted implicit address-of would let `(string-push-str (string-new) sv)` append into a temporary and drop it — gap #25's class of defect. Resolved: (1) **lvalue-only** implicit address-of — **implemented 2026-09-01**, covering every observed instance with no type-system change and keeping TC-3 the only materialization site; (2) **splitting `(ref T)`** — **deferred**, into read-only and mutable borrows, justified independently by signatures-as-documentation across 40,712 lines of `src/` (`(node-type n scope)` — does it mutate `scope`?), by making `ByteStr`'s "read-only" header comment enforceable, and by enabling LLVM `readonly` parameter attributes (behind attribute emission the compiler does not have yet); (3) full implicit address-of, which falls out of (2) for free. The sweep for (2) is kept small by letting `(ref T)` mean the read-only borrow and flipping the default, so the compiler enumerates the mutators — the shape of Stage 10's Phase F flip.

- [stage20-macros/computed-macro-arguments.md](stage20-macros/computed-macro-arguments.md) — Stage 20, **part four: computed macro arguments** — what it takes for `macmap` and the `:rest` family to take a computed argument rather than a literal one. Written as an evaluation of four options; **§2.1 at width (a) selected 2026-09-14**, phases `C1`–`C4` in §4. Two probes reframe it. First, **the capability already exists one level in**: `~` inside a macro body is ordinary code running at expansion time, and since part three that code may call the program's own functions, so a wrapper macro computing its rows with a `defn` and splicing them into a `macmap` **works today with no compiler change** (probed 2026-09-14, exit 13) — the baseline any feature has to beat is that, not "impossible". Second, at *source* level the same spelling is the error `unquote outside quasiquote` (`src/nucleusc.nuc:12246`), so **the marker is free**: a feature placed there lights up exactly the programs that are diagnostics today, and a `~`-wrapped macro argument already survives the reader inspectable (probed, exit 42). That makes the preferred option — `~expr` marks an argument for compile-time evaluation — not a new concept but the removal of an inconsistency, one rule instead of two, serving `macmap` **and friends** without touching any of them; `~@e` is needed alongside `~e`, since a `:rest` macro wants a computed list to arrive as N arguments. Its machinery mostly exists (`compile-time`'s `@__compile_time_main_N` compiles and runs; `emit-macro-expand` takes a `ptr` back and splices it) and its three sharp edges already have refusals built and tested by L5/L6/L8 (forward reference, cross-target, nested flush). Distinguishing atom from list is worse still: the `let`-over-`macmap` idiom it implies cannot exist, since a runtime binding is unreadable at expansion time. The reuse thesis is the whole stage and it held: `expand-macro-call` (`:11304`) is the single chokepoint where every macro argument is collected, and `compile-macro-body` (`:15858`) already compiles an arbitrary body into a CT module — so **a `~e` argument is compiled exactly like an anonymous zero-parameter macro body**, and the mirror, the closure walk, `--warn-ct-shadow` and all three of part three's refusals (L5 forward reference, L6 nested flush, L8 cross-target) are inherited rather than rebuilt. 195 lines of compiler change for a feature that needed none of that machinery written twice. - [stage20-macros/string-table-per-module.md](stage20-macros/string-table-per-module.md) — Stage 20, **part six: the string-literal table, one per module**. `S1` and `S3` **built 2026-09-15** (§6, §7); `S2`, the boot convergence, is open and **needs its own authorisation** because `make update-bootstrap` rewrites `boot/nucleusc.ll` *and* both committed Windows boot IRs. Promoted out of [deferred/overview.md](deferred/overview.md), where it was recorded as measurement without a fix, and it is the defect [stage20-macros/overview.md](stage20-macros/overview.md) §9.2 had to replace its byte-identical gate over: `g-strs` is **one vector per compilation** and `emit-string-table` writes **all** of it into whichever module is being assembled, so every macro body's quasiquote interned its symbol spellings into the table the *program* module emits — constants the program never references — and adding one macro to `lib/prelude.nuc` renumbered every string after it in every program. Two checks make the fix small and were made before planning rather than assumed: `intern-string` (`src/scope.nuc`) keeps **no dedup cache** (it appends unconditionally, id = position), so there is no companion map to reset; and private `unnamed_addr` constants are module-local, so a CT module's `@.str.0` and the program's cannot collide in the JIT. **The plan's swap does not survive its own exception, and that is the one delta.** §3 ruled that `ct-mirror-flush` must keep emitting the *program's* table, because it copies program `define` spans into the mirror module and those spans name program `@.str` ids — but `expand-macro-call` flushes a mirror before **every** macro expansion, and a macro body is itself compiled with `emit-node`, so a macro whose body calls another macro that calls a program defn builds a mirror **while the outer body's table is live**; `ct-mirror-build-init` reaches the same place from the other side, interning an initializer's strings into whichever table is live. "Leave the call alone" then means "emit the CT body's table", exactly what §3 forbids — measured, not argued: an eight-line program fails `use of undefined value '@.str.29'` under the swap, simulated on a throwaway build. Nor can the swap be patched, since the mirror would need *both* tables and both start at `@.str.0`. So `g-strs` is **never redirected**: each CT module path records `(count g-strs)` as a **watermark** in the same "redirect global state" `let` the plan named, `emit-string-table` takes that watermark as a `from` parameter and emits only `[base, end)`, and `strs-truncate-to` (beside `intern-string`, the `repl-vec-truncate` idiom) drops the tail once the module is assembled. Every reader keeps seeing the program's ids at all times, so the nested flush is correct **by construction** rather than by a restore someone has to remember, and a `die-at` that unwinds past a truncate leaves a few dead constants rather than a program without its table. §3's table also has **four rows where the tree has five call sites** — the fifth is `src/repl.nuc`'s, which assembles a REPL entry's own *program* module and therefore takes the whole table — and there are **two** swap sites, not three: `assemble-module-ir` is the one that stops carrying the others' strings and needs no watermark. **Measured:** a literal-free program 106 dead constants → **0**; a hello-world over `lib/io.nuc` 186 dead → **1**; `build/nucleusc.ll` 10,147 `@.str` → **6,237**, 3,911 dead → **0**, 13.94 MB → 13.53 MB (−405 KB, −2.9%); the two `macrolet` roster tables in `src/repl.nuc` 145 dead → **0** (§1's estimate of 125 was low). Options: **O1** a `nil` sentinel + read-only protocol split (small, leaves the AST source-only, and stale `(= n null)` guards go silent — a non-null ref compared to `null` is accepted with no diagnostic today); **O2** a header over the cons spine (same sweep as O3, O(i) index, tail-sharing mutation hazard); **O3, recommended** a header over an array — `Node`'s `car cdr` relaid as `elems len cap` at the same 40 bytes, `count`/index O(1), `~@` an extend (faster than today's cell-copying `@__append`), `rest` a copy-on-write view, `Node` conforming to the full `Coll`/`Seq` in `lib/node.nuc`, quasiquote/quote/`:rest` emitters rebuilt left-to-right, one boot refresh, gated by `--dump-ast` corpus identity; unblocks the Stage 14 deferred `&Node` AST API. O4 (wrapper struct) and O5 (nullable receivers) dismissed. A stage item the size of "one reader". **As built** (§8.6): O3, in two boot refreshes behind the layout-neutral list API of §8.2 — step 1 sweeps every `'car`/`'cdr`/`make-cell` onto the API with the representation unchanged, step 2 relays the struct. A macro body reads a list through four **special forms** (`ast-first`/`ast-rest`/`ast-at`/`ast-len`) rather than the `node-*` functions: a body is compiled from the *program's* prelude but handed the *running compiler's* nodes, and only a special form is lowered correctly under both layouts at once (the abandoned alternative, hand-written `declare`s in `lib/macros.nuc`, pins the very arity a relayout moves). Two mechanisms the relayout cost: **`node-kind` answers `NODE-NIL` for `()` as well as for null**, which is what preserved all twenty W9-item-45 diagnostics with none rewritten (ten sites that had to tell the two apart got a `node-empty?` guard); and **a literal quoted selector naming a field of the receiver outranks `invoke`** in the callable-value router (`callee-selects-field`), which is what lets a type be both indexable and a struct — `(n i)` indexes, `(n 'kind)` reads the field — and which forced the conformance to stage across two bootstraps, `Coll` plus the router fix first. Six surprises in §8.6, of which the sharpest are that quasiquote must build its lists at **line 0** (the fallback to the enclosing form is what blames the call site) and that `node-rest` is a borrowed view — wrong as a mutation target and wrong as a recursion spine, which is how `stamp-macro-lines` came to stamp only the first element. One genuine regression, caught by the IR gate alone: `type-node-to-c-decl` tested `(= plist null)`, so a C function-pointer return type printed `f()` instead of `(void)`. Sweep rule, now in `context/conventions.md`: **never compare a list to null to mean empty; ask `node-len`** — null means "absent" and nothing else. 1094 tests, bootstrap converged, both gates re-baselined with recorded reasons. §8.5's ergonomic follow-ups (`node-push` → `conj`, `node-at` → `(x i)` in the compiler's own reads, the `&Node` promotion, retiring `lib/list.nuc`, the `(= r null)`-on-a-ref diagnostic) are unblocked, not done.

- [stage23-namespaces/quasiquote-resolution.md](stage23-namespaces/quasiquote-resolution.md) — Stage 22 follow-on, **quasiquote names resolve where the macro was written** (designed 2026-10-03, D1–D5 accepted; HY-0 … HY-6 built 2026-10-03; **rebased onto full names by Stage 23 AN-4, 2026-10-04: the tag is gone and D3 is reversed**). This is Clojure's syntax-quote rule adapted to Nucleus. A symbol in a data position of a compile-time-module quasiquote that names a global of the defining file becomes an unforgeable tagged spelling `#hN/name`. Reference resolvers resolve it inside that file's `NameEnv`, the mechanism templates already use. - [stage23-namespaces/ambient-namespaces.md](stage23-namespaces/ambient-namespaces.md) — Stage 23, **ambient namespaces: revisiting Stage 15 R3** (analysis 2026-10-03; ruled and planned in §8; **AN-1 built** — closure reach, `require`/`require-ct`, dotted library names; **AN-2 built 2026-10-04** — core libraries moved to `lib/nucleus/` as `nucleus.*` with bare link names, `nucleus.core` prelude; **AN-4 built 2026-10-04** — quasiquote names are full names, the `#hN` tag machinery deleted, D3 reversed). It weighs Clojure-style reach to a namespace by its full name, plus `require`/`require-ct` as imports that bind nothing. Scoping reach to each file's **import closure** is recommended over load order or the whole unit, because it keeps resolution order-free and gives a file the same meaning in every program. The cost is mostly semantic: R3's "a library's imports are not its API" is lost, and namespace names become API. The implementation is modest and existing IR stays byte-identical. Rebasing the quasiquote work on full names would delete the `#hN` tag machinery: about 140 lines plus 39 resolver call sites, output scrubbing and `.nuch` re-spelling. The price is the D3 private-name reach.

- [stage23-namespaces/typed-c-pointers.md](stage23-namespaces/typed-c-pointers.md) — Stage 23 follow-on, **typed C pointers** (investigated, ruled and built 2026-10-05; as-built in §6). A C `T *` imports as `(ptr T)`, so C calls are pointee-checked. The exceptions are byte signedness (Q1 (a)), a C type's several names, and an implicit first-member upcast (Q2). `size_t` → `usize`. - [stage24-allocation/overview.md](stage24-allocation/overview.md) — Stage 24, **allocation and initialization** (designed 2026-10-07; AL-0 … AL-6; Q1–Q6 ruled 2026-10-07, all as recommended, Q5/Q6 to revisit after use). Nothing extends `Allocator`; collections dispatch through a two-kind tagged `AllocHandle`; the arena is a process singleton that loses its old blocks; each collection has its own prefixed constructor family. Proposes `Heap`/`Arena`/`Stack` allocators conforming to `Allocator` and `Drop`, `Init`/`InitFrom`/`TryInitFrom` protocols, and `new` (allocator placement) / `make` (by value) as the single-call forms. Recommends that dropping an allocator with live objects be a contract, checked where cheap, not automatic finalization. Found two bugs: a user function named `init` breaks `for`, and a user method named `free` or `realloc` breaks the library's libc calls.
- [stage24-allocation/conformance-query.md](stage24-allocation/conformance-query.md) — Stage 24, **asking about conformance at expansion time** (analysis and build 2026-10-07; CQ-1 … CQ-4 built, §8 records the differences). `(conforms? t P)` uses the same plumbing as `struct-fields`. Four things have to change for it to answer correctly. `extend` is recorded in source order: dispatch already fails on an extend below the call, and a query would answer "no" without an error. The A2 generic check expands macros with `T` unbound (`struct-fields` already fails there with a flat type variable). The protocol has to resolve in the macro's file. Parametric protocols need their arguments compared. As built, a written `extend` is a promise redeemed by dispatch and `conforms?`, and a `conforms?` no is enforced against later conformances.
